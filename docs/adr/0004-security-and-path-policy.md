# ADR-0004: 安全与路径策略

## 状态

Accepted（2026-08-02），**Amended（2026-08-19，见 Amendment 1 / Spike S4 / Spec #84 P0）**

## 上下文

ADR-0001/0002 原稿完全未提及安全，而本项目是**面向公开发布的产品**（Issue #1），其读侧能力本质上是「按路径读取源码与元数据并返回给模型」。威胁面：

- MCP 服务器以用户身份运行，能读用户账户可读的一切文件。若 `workspace_open` 接受任意路径，一个被提示注入的模型可以让服务器打开 `~/.ssh`、凭据目录、其他仓库并把内容回传。
- 加载解决方案会**执行代码**：MSBuild 求值会运行 SDK/自定义 target，Roslyn 运行 analyzer/源生成器——都是第三方代码。打开不受信任的仓库等于执行其构建逻辑。
- 生成文档、诊断消息、XML 文档注释都会进入返回内容，可能夹带针对上游模型的提示注入文本。

先行实践：darylmcd-Roslyn-Backed-MCP 有 sanctioned-root 限制（拒绝会话仓库外的路径），Argha713-dotnet-mcp-server 有路径白名单 + SQL 只读 + HTTP 白名单 + 审计日志。

## 决策

### 1. 受信根（sanctioned roots）

服务器启动时确定一组受信根（启动参数/配置/环境变量；缺省为当前工作目录）。所有路径参数必须解析后落在某个受信根之内，否则拒绝并返回可操作错误。

- 路径先规范化（完整路径、解析 `..`、解析符号链接/junction）再比对前缀，避免遍历绕过。
- 拒绝时**不回显目标路径内容**，仅说明策略。

### 2. 明确的"打开即执行"告知

文档与 `workspace_open` 的工具描述必须写明：加载解决方案会运行 MSBuild 求值与该项目引用的 analyzer/源生成器，等同于在该仓库执行构建逻辑；不要对不受信任的代码库使用。这是一个**不可通过技术手段消除**的性质（Roslyn 语义分析必须加载这些程序集），只能显式告知。

### 3. 默认只读 + 显式 opt-in 的受限 Workspace Edit

默认工具面仍是读：导航、分析、诊断、归因。**不**提供通用写文件、补丁、命令或网络工具。

2.0 起允许一类显式 opt-in 写：`symbol_preview_rename`（及后续 `symbol_apply_rename`）构成 Workspace Edit 合同。Preview 不写盘；Apply 只写 preview 已声明且落在受信根内的已有解决方案文档，并必须套 `WriteSuppression`（Spike S4）。

工具表面清单快照测试继续挡住 `apply_edit` / `patch_file` / `write` / `shell` / 网络碎片；允许名单只增加 rename 两步（本票只加 preview）。

### 4. 输出侧的注入意识

返回内容（源码片段、诊断消息、生成代码、XML 注释）视为**不可信数据**，不得由服务器自行解释为指令；结构化输出中对其明确标注来源（文件路径/生成器身份，见 ADR-0001 归因），使上游模型与用户能判断出处。

### 5. 不记录敏感内容

日志记录操作与路径元数据，**不记录源码正文**；日志默认落在用户本地、可关闭；不发送任何遥测到外部。

### 6. 拒绝而非静默降级

策略拒绝、工作区未就绪、符号不存在三类情况必须可区分且各有 `SuggestedAction`——静默返回空结果会让模型编造解释。

## 后果

- `workspace_open` 增加受信根校验，多仓库场景需用户显式配置额外根。
- 需要一份面向用户的安全说明（README 的安全小节）：受信根、打开即执行、只读、日志。
- 工具表面清单需有快照测试以守护"只读"承诺。
- 路径规范化需覆盖 Windows 特有情形（大小写不敏感、UNC、junction、`\\?\` 前缀）——列入实现清单。
