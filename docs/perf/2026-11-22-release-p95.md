# DotNetMCP 5.0 release latency verification

Compared the last published 4.x release (`v4.0.1`, `13894f5`) with
`v5.0.0` (`33935fb`) on the same Windows 10.0.26300 host, with .NET SDK
10.0.303, runtime 10.0.15, and Release builds. The 5.0.0 harness added the
two new symbol scenarios in this change. Product code came from the tags.

Both releases used clean tracked-source exports with the same subject
revisions and no carried-over subject restore or build outputs. Runs used
one warm-up and five measured calls per scenario. Workspace open and ready
were measured once per workspace. Exact rows and error classifications are
in [the comparison CSV](2026-11-22-release-p95.csv).

| Suite / pinned subject | 4.0.1 units | 5.0.0 units | Comparable timing rows above +20% | 5.0.0 absolute harness |
| --- | ---: | ---: | ---: | --- |
| Fixtures | 3 / 3 / 1 | 3 / 3 / 1 | 11 / 64 | pass |
| FluentValidation `daa00b7` | 6 | 6 | 7 / 16 | required callers returned `SymbolNotFound` in both releases |
| Serilog `49b5339` | 19 | 19 | 8 / 17 | pass |
| Spectre.Console `0acc92f` | 29 | 29 | 7 / 17 | batch diagnostics p95 15.04 s against 15 s in 5.0.0 |
| Observables `6774626` | 223 | 293 | 7 / 17, changed graph size | ready and drift exceeded the absolute budgets |

Across matched non-error rows with the same loaded project counts, 33 of 114
exceeded +20%. Four additional same-count rows contain an error and two
are new scenarios. The reported p95 was 0.8 ms for `symbol_source` and 2.6 ms
for `symbol_resolve_at`. Small timing changes can cross a relative threshold
at this sample size, but `workspace_check_drift` grew by hundreds of
milliseconds on each of FluentValidation (649 → 967 ms), Serilog
(910 → 1,302 ms), and Spectre.Console (1,723 → 2,527 ms).

On Observables, open-to-ready grew from 25.4 s to 140.1 s while the loaded
graph grew by 70 units. The absolute 60 s ready target still failed. Treat
the relative difference there as a result for the whole open path and its
changed coverage. The p95 cap in #529 remains unmet.

## Drift follow-up on the 5.1 development branch

Re-ran `workspace_check_drift` against the same three OSS sources with
two warm-ups and nine measured calls per version. The candidate reused
canonical graph paths for read authorization. The current filesystem target
was still resolved and checked before file content was read.

| Subject | Baseline `ae59618` p95 | Candidate p95 | Change |
| --- | ---: | ---: | ---: |
| FluentValidation | 962 ms | 405 ms | −58% |
| Serilog | 1,159 ms | 479 ms | −59% |
| Spectre.Console | 2,194 ms | 793 ms | −64% |

This experiment measured only drift. The full release comparison above
continues to describe the published 5.0.0 tag.

To repeat, build the benchmark at each release and run `--suite fixtures`
and `--suite scale --solution <path> --symbol <query>` with
`--iterations 5 --warmup 1`. Use the paths and queries in
[OSS results](oss-results.md). Save a separate JSON per subject and release,
then compare with
`python benches/compare_p95.py --pair <subject> <4.0.1.json> <5.0.0.json>`.
The operator's raw captures are under
`artifacts/release-p95-401-vs-500/{401,500}/`.
