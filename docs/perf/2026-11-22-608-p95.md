# 5.1 p95 acceptance for #608

## Initial reproduction

Compared `v4.0.1` (`13894f5`) with the starting candidate `8595efa`. Both
benchmarks were built in Release using SDK 10.0.303 and ran serially on the
same Windows 10.0.26300 host (.NET 10.0.15, 20 logical CPUs). Every tracked
subject was extracted from `git archive` for each process with no subject
restore or carried-over `bin` and `obj` directories. Both fixture arms used
the tracked `tests/fixtures` tree from `8595efa`. The harness generates
XamlApp in a fixed path under the process temp directory. The initial runs
shared that path, which contained old `bin` and `obj` directories. Those
XamlApp rows are retained as initial observations and need a clean rerun.

The initial run used one warmup and five measured calls per scenario.
`workspace.open.return` and `workspace.open.ready` have one sample per
workspace. The nearest-rank p95 of five calls is the maximum. The comparison
requires matching scenario IDs, matching ready project counts, and no
reported errors. See [the initial comparison CSV](2026-11-22-608-initial-p95.csv)
for counts and timing deltas, including rows excluded from the cap.

| Suite / subject | Baseline units | Candidate units | Comparable rows over +20% | Candidate gates |
| --- | ---: | ---: | ---: | --- |
| Fixtures (SampleFilter, MixedWithFs, XamlApp) | 3 / 3 / 1 | 3 / 3 / 1 | 25 / 63 | pass |
| FluentValidation `daa00b7` | 6 | 6 | 4 / 16 | pass |
| Serilog `49b5339` | 19 | 19 | 5 / 17 | pass |
| Spectre.Console `0acc92f` | 29 | 29 | 8 / 17 | pass |
| Observables `6774626` | 223 | 293 | changed load coverage | pass |

The initial candidate exceeded the relative cap in 42 of 113 comparable
rows. The full Observables workspace returned in 53.5 ms and reached ready
in 35.7 s. The tagged baseline reached ready in 109.1 s with 223 units.
Four rows have an error on at least one arm. Two new fixture scenarios have
no baseline. The FluentValidation callers row has a baseline
`SymbolNotFound` because that harness selected a property handle. The
previous release comparison also had `SampleFilter.diagnostics.list_fixes`.
Both current arms omitted it because the fixture's LibA diagnostic probe
returned no item on the clean input. This accounts for the change from
114 to 113 comparable rows.

## Final verification method

Use the most recent full tagged `v4.0.1` captures and a fresh candidate
run of all five suites for the five-sample comparison. Repeat the entire
fixture suite and the same-count OSS navigation cases in three fresh
process pairs with five warmups and 30 measured calls. Use the median
of the per-process p95s for repeated rows and keep each raw p95 in the
CSV. Recheck any other five-sample row that exceeds +20% in independent
pairs before signoff. The coverage and absolute limits still apply to
the full candidate run.

## Reproduction commands

Create a worktree for each revision and build the harness in Release with
SDK 10.0.303. The 4.0.1 tag predates the repository's `global.json`, so pin
that SDK in its worktree when multiple SDKs are installed.

```powershell
git worktree add --detach <baseline-checkout> v4.0.1
git worktree add --detach <candidate-checkout> 8595efa
dotnet build benches/DotNetMcp.Bench -c Release
```

Run the build command from each worktree. Export each pinned subject using
`git -C <subject-checkout> archive --format=zip -o <archive> <revision>`, then
unzip into a fresh directory for each process. Use a neutral parent directory
to avoid inheriting local `Directory.Build.props` or
`Directory.Packages.props`. For both fixture arms, extract the `8595efa`
archive of `tests/fixtures` as `fixtures` beside a fresh copy of the
benchmark binaries. Below, `$bench` is the absolute path to that arm's
`DotNetMcp.Bench.dll` and `$out` is a new output directory for each run.
Set `TEMP` and `TMP` to a fresh directory for each fixture process so its
generated XamlApp starts clean as well.
For a candidate rerun, create the candidate worktree at the commit named
in the corresponding section above.

```powershell
dotnet $bench --suite fixtures --iterations 5 --warmup 1 --out $out
dotnet $bench --suite scale --solution $solution --symbol $symbol --iterations 5 --warmup 1 --out $out
python benches/compare_p95.py --pair <subject> <baseline-json> <candidate-json>
```
