# DotNetMCP task-level A/B evaluation

The formal run used Codex CLI 0.166.0 and OpenCode Go
`deepseek-v4.1-flash` in WSL Ubuntu 24.04. The tool arm used the
`Skymly.DotNetMcp` 5.1.0 development package built from `fd85a2d`.
Its product source tree matches the subsequent main commit `ae59618`.
The candidate was frozen when scoring began.

The ten tasks ran three times per arm with an identical 1,200 s limit. Cells ran
serially, and each repetition used a fresh, identically prepared source
copy and Codex home. Arm order alternated. The tool arm added only the
DotNetMCP stdio server and its initialize instructions. See the
[task-bank prompts and grading rules](task-bank/README.md).

Workers used Bubblewrap mount isolation. The controller, answer key, other
trials, Windows filesystem, and API credential were outside the worker.
Source was read-only for tasks without edits, with writable build
scratch directories. A3 and D1 permitted writes to their disposable
subject. The grader compared their source bytes with the pinned expected
edits. For an exact match, it built a separate golden copy.

The general worker used .NET SDK 10.0.303. The MAUI worker used SDK
9.0.321 with the Android workload, Android Platform 35, and JDK 17.
Both MAUI arms used the Android target of the same pinned app and the
same pinned resource submodule. C1/C2 used the Serilog library project,
with the full pinned source available.

## Results

All 60 cells finished. The control passed 28/30 and the tool arm passed
30/30. Every task category met the completion-rate criterion. Costs are
medians over all cells in the category, including incorrect runs.

| Category | Control correct | Tool correct | Wall s (C / T) | Input tokens (C / T) | Output tokens (C / T) | Calls (C / T) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |

| Cross-project | 6/6 | 6/6 | 14.4 / 23.6 | 27,194 / 95,901 | 993.5 / 889 | 4 / 4.5 |

| Text control | 6/6 | 6/6 | 11.0 / 15.9 | 17,676.5 / 43,129.5 | 392 / 448 | 1.5 / 2 |

- The two incorrect control runs were A3. One changed XAML indentation.
  The other renamed a comment. The task allowed identifier changes only.
  The tool arm consulted a rename preview once and used host edits in all
  three runs. These results measure the two configurations as a whole.
- Generator attribution used MCP in all three tool runs and finished faster
  at the median. Cross-project, binding, and text control took longer and
  used more input tokens with the tool attached. The tool arm made 57 MCP
  calls across nine cells. The diagnostic-fix cells used host tools.
- The MAUI preflight found that the frozen server missed XAML 2009
  directives. The formal MAUI cells used text to answer the binding
  questions. Issue #598 separately fixed and verified the semantic path on
  the pinned app.

This formal gate passed after 5.0.0 had shipped. The published release's
latency result is tracked in #529. See the
[release latency comparison](2026-11-22-release-p95.md).
